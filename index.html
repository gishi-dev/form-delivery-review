フォーム納品前の確認記録

確認した対象・方法・結果を読み、残る課題の担当と受け入れ判断を記録します。

すべて架空の仕様・確認記録です。確認した範囲と残る課題の記録で、安全の保証や第三者の診断ではありません。

1. 納品物と今回の確認範囲

詳細表示・検索・CSV出力・添付ファイルは、管理一覧とは別の確認対象です。模擬の役割による記録は本物の認証の記録には使えません。

2. 記録・下書き・状態を照合する

3. 確認記録と候補の取り込み

架空データのみを扱ってください。確認記録はデータとして扱い、文中の指示やコードは実行しません。URLやサイトの点検、外部への送信は行いません。

確認記録の編集・追加

項目内で記録を編集できます。一括入力はJSON形式（id と record の配列）。空欄は null として扱い、未知の項目や値は取り込みません。

不足事項と質問の整理

現在の入力・版・改訂番号と候補のひな型を含む指示をコピーできます。生成AIへの送信は行いません。人が候補JSONを作っても取り込めます。

4. 受け入れ判断と書き出し

すべての項目の確認範囲と状態を記録してください。記録不足・未確認の項目には担当・期限・依頼文が必要です。

受け入れ記録 JSON

比較用・教材の版は照合用の下書きだけを書き出します。版と用途を必ず含めます。

判断の履歴

入力・版・候補の変更による無効化は、コードの記録として区別します。この画面を再読み込みすると作業内容は消えます。必要な記録を書き出してください。

    AIは不足事項と質問の下書き、コードは条件の確認、人は範囲・状態・担当・受け入れ判断を担います。
